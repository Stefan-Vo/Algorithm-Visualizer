    How it works

    Not an animation. A recording of a real execution.

    Many visualizers play a pre-made animation that only looks like the algorithm. Here the algorithm actually runs, and every step it takes is recorded along with the exact program state at that moment. Everything you see is drawn from that record.

    One step, fully explained

    This card was generated from a real recorded step of insert(root, 6). The engine knows which line is running, what every variable holds, what is being compared, and which way the algorithm will go next.

    Because the whole run is recorded, Previous, the timeline slider and jump to comparison are exact. Nothing is re-simulated or faked backwards.

    Features

    Everything a learner (or an interviewer) wants to see

    Line-by-line sync

    The current line is highlighted, and lines where outer calls are paused are marked, so recursion is easy to follow.

    Variables & call stack

    Every frame's locals, what just changed, return values, and each comparison with its live values: 7 < 10 → True.

    Recursion tree

    Every call as a node with its arguments and return value. Compare naive and memoized Fibonacci and see the difference immediately.

    Paste your own Python

    Real CPython runs in your browser via WebAssembly. Trees, linked lists, arrays, grids and dicts are detected and drawn automatically.

    Full playback control

    Play, pause, step forwards or backwards, scrub the timeline, change speed. Keyboard: ← → Space C.

    Checked for correctness

    Every algorithm is tested against a reference implementation on thousands of random inputs, including the recorded steps themselves.
